# требования к безопасности

- каналы связи через TSL 1.3
- списки допустимых ip
- все операции с домофонами и шлагбаумами логируются (userID, deviceID, time)
- биометрия - хранится только хеш
- передача биометрических данных - только минимально необходмое
- централизованный аудит
- настроеннв siem 

# протоколы аутентификации и авторизации

- мобилное приложение - auth 2.1 
- межсервесные взаимодействия - mTLS + OAuth2 Client Credentials
- администрирование - централизованные политики безопасности (RBAC + ABAC (OPA / Gatekeeper))

# взаимодействие между системами предприятия и внешней платформой

[mobile app] -> [prodev api geteway] -> [service layer] -> [audit + monitorint]
                                        [service layer] -> [partners services]

- пользователь открывает дверь или шлагбаум через уже существующее приложение, приложение отправляет запрос на сервер PropDev
- сервер проверяет, что пользователь авторизован и имеет разрешение на действие - затем сервер формирует безопасный запрос к платформе партнёра
- интеграция с платформойб обмен данными идёт через защищённый канал (HTTPS/mTLS) и с токеном доступа (OAuth 2.0).
В запросе указываются идентификаторы жильца, объекта и команда (например, открыть дверь или поднять шлагбаум).
- платформа (умный дом) получает команду, сверяет разрешения в своей системе и управляет устройством (домофон, шлагбаумом), возвращает ответ о статусе выполнения команды.
- все события логируются
